# ClaimTrace backend

The standalone incomplete investigation agent is documented in [controller usage](../docs/investigation-controller.md). It reuses the readers below, adds bounded deterministic verification/challenge/recheck and actual [H-MEM reviewed memory](../docs/hmem-integration.md), and works without the frontend. Existing `/api/investigations` behavior remains compatible. No live model reasoning is performed.

From the repository root, use `.venv/Scripts/python -m pip install -r backend/requirements.txt`, then `.venv/Scripts/python -m uvicorn backend.main:app --host 127.0.0.1 --port 8000`.
Run `.venv/Scripts/python -m pytest backend/tests -v` for tests. Vite proxies `/api` to this local backend. No model request runs on application startup or investigations.

`CLAIMTRACE_SEC_MODE=cache_first` (default) serves the authentic ISRG 2026 Q2 snapshot only for that company/period, with `cached_sec` attribution and source hashes. Other requests use live SEC Companyfacts. Set `CLAIMTRACE_SEC_MODE=live` to bypass the snapshot. Live access requires `SEC_CONTACT_EMAIL` containing your real monitored owner-approved bare email. The application constructs `ClaimTrace Hackathon Team <email>` as the SEC User-Agent. Supply it locally; do not commit contact or credential configuration. SEC requests use a 20-second timeout, process-wide 2 requests/second maximum, 15 MB response bound, no redirects and no retries. Multiple server processes need a shared rate limiter before scaling.

The selector uses SEC reporting filing fiscal-year/period fields plus exact quarter (70–105 days) or annual (330–380 days) durations. It excludes six/nine-month values from quarter labels. Some issuers do not disclose a standalone Q4; these requests can return no evidence. It does not derive Q4 or silently substitute FY/YTD. Publication filtering uses SEC filed dates, conservatively excluding issuer releases published earlier. This is a limited evidence foundation, not a complete earnings brief or a financial recommendation.

SEC identity configuration loads only `SEC_CONTACT_EMAIL` from the repository's Git-ignored `.env.local`; the process environment overrides this value. Enter only the real monitored owner-approved bare email. The organization is fixed to `ClaimTrace Hackathon Team`; raw `SEC_USER_AGENT` overrides are ignored. Missing/reserved example domains, `.invalid`/`.test` contacts, GitHub noreply addresses, no-reply contacts and explicit placeholder local parts are rejected before any network request. The application cannot verify email ownership from its shape: a human-approved actual contact is required. Keep only an obvious placeholder in committed `.env.example`. No real contact was invented or configured by this change. Retrieval deliberately makes no automatic retry after429/503; it stops with a sanitized unavailable response, avoiding repeated requests during SEC throttling. After429/503, wait for the service's requested delay before a separate explicitly initiated attempt.

Zetaris uses `ZETARIS_CONFIG_PATH` pointing to the owner's existing external secure configuration, or server environment values `ZETARIS_BASE_URL`, `ZETARIS_ORG_ID`, `ZETARIS_API_KEY`. Values are never returned by the API. `CLAIMTRACE_ZETARIS_TABLE` must name an approved existing financial table. No application writes are implemented. Existing SQL proxy shape is reused: POST `/api/proxy/sql-editor/sqls/run-query`, Bearer + X-Org-ID + X-Request-ID, bounded limit. No fallback endpoint is guessed. Initial discovery found only sample databases; subsequent owner-approved setup created the isolated ClaimTrace SEC REST tables/view. Actual `claimtrace.sec_financial_evidence` financial SQL and API acceptance succeeded on 2026-10-23; see `../work/live-data.json` and `../work/live-qa.md`. Configure that approved view in the backend process to use live Zetaris mode. No CREATE statement runs during investigations.

`providers/meterless_client.py` is the nonsecret portable client reused from HQ preparation work, with default application ID changed to `claimtrace`; original 13 local HTTP/mock tests are preserved. It normalizes approved HTTPS or loopback endpoints, prevents redirects, keeps the runtime token private and discovers real `meterless/` routing IDs. Construction performs no network call. `providers/interfaces.py` preserves the original boundary protocols. The actual H-MEM/controller integration now lives separately in `backend/investigation/`; live Nightshift/Nemotron acceptance remains incomplete. Do not call chat until inference and supported runtime access are explicitly authorized.

See `providers/provenance.md` for pinned original H-MEM/Meterless sources, portable adapter modifications, server environment names and the bounded future live acceptance plan. The default adapter caps output at128 tokens and input at12000 characters. The normalized Zetaris schema requires canonical identity, explicit fiscal labels and a verified reporting-period end alongside each fact; generic query validation rejects mismatches. The approved initial view in `data/zetaris-proposal.sql` is intentionally limited to five authentic ISRG Q2 facts across current/prior periods; its creation and financial reads are now verified. The SQL file is an executed setup template, not an application migration to rerun.
