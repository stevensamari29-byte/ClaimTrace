# Reuse and acceptance boundaries

Portable Meterless client code and 13 local HTTP/mock tests were copied from the owner's existing tested HQ preparation adapter; no configuration or credential was copied. Changes: module namespace for product tests, default stable app ID `claimtrace`. This is real code reuse and local protocol verification, not live Nightshift inference. `interfaces.py` retains the original source-backed boundary; current application memory is implemented separately in `backend/investigation/memory.py` and exercised in product tests and recorded sourced-recall acceptance.

The preserved provider contract is pinned to [Meterless commit 1742dec56a66e58eef9dda2d2b865823758ca8cd](https://github.com/Meterless/Meterless/blob/1742dec56a66e58eef9dda2d2b865823758ca8cd/docs/agent-ready/add-meterless-provider.md), declaring Runtime 0.90.0. Existing H-MEM work is pinned to [commit 1742dec56a66e58eef9dda2d2b865823758ca8cd](https://github.com/Meterless/Meterless/tree/1742dec56a66e58eef9dda2d2b865823758ca8cd/engines/hmem/reference); its 13/13 reference tests were previously recorded passing. It uses deterministic mock embeddings by default; this is not learned semantic recall. No redundant H-MEM installation was performed and no private reference/configuration files were copied. The original reference work remains preserved in HQ. Five unchanged public modules are now vendored with their Apache 2.0 license and source hashes under `backend/investigation/vendor/hmem/`; no private HQ records or configuration were included.

Official configuration remains OpenAI-compatible `/v1/models` + `/v1/chat/completions`, server-side Bearer runtime token, `meterless-app: claimtrace`, and `meterless-scope: user` on inference. Preserve Nightshift as primary intended runtime. Use server-side environment names `NIGHTSHIFT_BASE_URL`, `NIGHTSHIFT_RUNTIME_TOKEN`, `NIGHTSHIFT_MODEL_ID` (a real routing ID discovered from `/v1/models`), `NIGHTSHIFT_INFERENCE_ENABLED=false`. No startup probes/inference. Do not infer model readiness from `/healthz`, a port, imports, or mocked responses. No credential values belong in Git, browser code, screenshots or reports.

Live acceptance remains blocked pending supported Nightshift host/hardware, real authorized Runtime token, a discovered Nemotron model route, and explicit inference authorization. After those exist: (1) construct `MeterlessClient(base, token, app_id='claimtrace')`; (2) discover once with timeout10; require the selected real `meterless/` routing ID; (3) issue exactly one nonstreaming completion with `max_tokens:128`, timeout180, one tiny source-backed prompt; (4) record model routing ID, real returned text, elapsed time, no token, and stop after one request. Product changes add a 128-token output maximum and 12000-character input maximum to `chat`; no acceptance request has run. `nightshift.configured_runtime()` reads the server environment only with explicit inference opt-in and performs no requests on construction. A successful response must then be exercised through the investigation controller before claiming product model integration.

H-MEM reference conformance alone is not product integration. The current standalone `backend/investigation/` controller and H-MEM adapter perform actual source-linked local recall, explicit exact-payload reviewed correction writes, persistence and supersession; see `docs/hmem-integration.md` and `work/agent-qa.md`. Reviewed memory adds context and never changes financial facts or numeric verdicts. Hash embeddings remain deterministic mocks; no live model inference, autonomous process or new model team is introduced.

Nightshift's `meterless/` identifiers are routing modes, not proof of the underlying NVIDIA model. Competition acceptance must capture a supported runtime receipt/configuration establishing actual Nemotron execution as well as the successful application request. Keep unsupported host/hardware/access as explicit blockers; no new inference runtime was installed.
