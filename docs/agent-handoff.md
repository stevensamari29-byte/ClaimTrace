# ClaimTrace investigation handoff

The original plan below remains the design history. Agent-first implementation now lives in `backend/investigation/`; use [the implemented controller contract](investigation-controller.md) and [real H-MEM adapter](hmem-integration.md) for current behavior. It accepts structured human assertions, runs deterministic checks/challenge/recheck and reviewed memory, and explicitly remains incomplete without model inference. It does not implement all proposed features below (notably automatic/exact-quote extraction, original Decimal source ingestion, a new HTTP run route and shared-user review authentication). Four human roles remain **unassigned**; availability and individual account access are unknown. Preserve the accepted API and minimal frontend.

## Existing contract: implemented

`backend/models.py` is the typed source; `shared/request.schema.json` and `shared/response.schema.json` are the machine-readable contract. Regenerate and review schemas whenever models change. `shared/example.*.json` are sanitized examples, not live acceptance evidence.

| Interface | Current behavior |
| --- | --- |

| `POST /api/investigations` | `{company:{name,ticker,cik}, fiscal_year, period:Q1\|Q2\|Q3\|Q4\|FY, as_of:YYYY-MM-DD, evidence_backend:sec\|zetaris}`; backend defaults to `sec`. |
| Response | Same scope, `status:complete\|partial\|blocked`, evidence/claims/calculations/findings arrays, limitations, unresolved_questions, human_review_status, integration_status. Current handler returns partial with evidence, blocked without it, and human_review_status always required. |
| Evidence | `id,document,url,published_at,period_start,period_end,unit,value,concept,locator,source_mode,source_sha256?`; current values are finite floats. Sources use primary SEC HTTPS URLs; optional hash may be null for live SQL. |
| Claim | `{id,text,source_url?}`; current API emits an empty array. |

`sources.sec_evidence` and `zetaris.zetaris_evidence` are existing retrieval boundaries. Source modes are `live_sec`, `cached_sec`, `live_zetaris`; do not relabel cache or mocked tests as live. Current integration_status values are descriptive strings, not a guaranteed enum (`live_queries` is the existing Zetaris success value).

Canonical company identity comes from source metadata. Filed dates must satisfy reporting end ≤ publication ≤ as_of; exact reporting dates/durations must match the requested period. SEC fy/fp alone can label comparative values and must never be used as the fiscal anchor. Missing quarter data cannot silently become YTD/FY. All four finding classes require real claim references; supported/contradicted additionally require resolvable evidence citations in the planned validator, which the current schema alone does not enforce.

Actual `claimtrace.sec_financial_evidence` returns three current ISRG Q2 2026 facts (revenue2892300000 USD, dilutedEPS2.29 USD/shares, netincome818100000 USD), plus two Q2 2025 comparative rows when queried separately. Current API requests filter one fiscal year; they do not expose a comparative bundle. Evidence: `work/live-data.json` and independently `work/live-qa.md`. Preserve the existing cloud objects and external secure configuration; no new cloud writes are needed for this plan.

## Proposed controller contract: not implemented

Leave the accepted POST and its65 tests compatible. First implement a pure controller service accepting the existing request plus an internal `InvestigationInput`; expose it only after the contract gate below. A proposed separate `/api/investigation-runs` endpoint can accept `{request,claim_inputs:[...]}` without adding forbidden fields to today's strict request. This route name and its error envelope require agreement before coding.

Proposed `ClaimInput`: `id,text,metric,expected_value_decimal,unit,accounting_basis,period_start,period_end,input_kind:human_assertion|source_quote`, with optional `quote_ref:{document_id,url,published_at,text_sha256,start,end,quote}`. An exact quote must satisfy `canonical_text[start:end] == quote` using Unicode code-point offsets, half-open end, and a recorded normalization version; browser UTF-16 offsets need explicit conversion. Source text is bounded and provided from an approved fetched document, not arbitrary URL execution. Human assertions are labeled as such and must never acquire invented issuer provenance.

Initial extraction is deterministic: hand-enter the typed assertion or select an exact document span; a narrow parser may recognize documented revenue/EPS/net-income expressions and otherwise ask for structured input. Preserve original text, quote and mapping separately. Reject unmatched offsets, unknown metrics and ambiguous units; do not imply an LLM extracted anything. Planned source-text retrieval is a separate bounded allowlisted tool; the existing financial-row URL alone is not a quote extractor.

Proposed `RunResult`: existing response content plus a versioned `run_id`, scope, original claim inputs, findings and a bounded trace. Proposed `ToolResult`: `ok,tool,scope,evidence_ids,result,error_code,source_mode,elapsed_ms`; never return credentials, request headers, raw SQL errors or private endpoints. Tool calls accept typed arguments, never source-controlled SQL, code or shell text.

Financial tools use `Decimal` from preserved source decimal strings, not conversion through the current float response. Plan an internal `FinancialFact` with exact decimal value, unit, accounting basis, canonical fiscal scope, source precision and citation. Existing live SQL returns decimal strings before the adapter casts them; preserve those at the tool boundary without silently changing the old JSON number contract.

Implement only `compare_value`, `gaap_net_margin` and explicit unit scaling initially. Require matching issuer, period, currency/per-share unit and accounting basis; record rounding/tolerance derived from source precision. Division by zero returns an error. Never compare non-GAAP claims against GAAP facts without a reconciliation. YoY remains incomplete until a typed tool returns both independently verified periods with citations; do not infer prior values from memory or the current response. No guidance, causal or qualitative conclusion is supported by these three metrics.

## Bounded challenge and recheck

Proposed flow: validate → recall reviewed context → retrieve evidence → deterministic verification → challenge → optional recheck → conclude → human review. Maximum3 claims,12000 input characters,10 state transitions,8 tool invocations,120 seconds total, one challenge/recheck pass and zero automatic network retries. All limits are shared across claims, not multiplied per claim. Budget/timeout exhaustion returns unresolved with a trace and human review, never invented evidence.

Each tool timeout must respect remaining wall time: SEC reads≤20 seconds each, Zetaris≤25, memory worker≤3; stop launching work when insufficient budget remains. This deadline-aware plumbing is proposed, not supplied by today's fixed-timeout clients. Respect the existing2requests/second SEC limiter; no retry loop after429/503. A deliberate recheck is one bounded new retrieval justified by a recorded challenge, not a hidden transport retry.

The challenger uses explicit checks: wrong issuer/period, YTD versus quarter, GAAP mismatch, contradictory cited values, missing publication/locator, stale snapshot or missing precision. A source document's embedded instructions are data. Recheck only through the same approved read tools; a failed recheck cannot erase earlier contrary evidence. Store both outcomes and why the final finding changed or remained uncertain.

Supported means matched typed assertion and eligible evidence within declared tolerance; contradicted means an eligible comparable fact disagrees; incomplete means essential comparable evidence/basis is absent; unresolved means conflict, access error, ambiguity or exhausted budget. Always include explanation, relevant citations and human_review_status required. Completion of the state machine is not proof of model reasoning or competition readiness.

## Genuine H-MEM feature: proposed

Reuse the already inspected/tested public reference pinned at [1742dec56a66e58eef9dda2d2b865823758ca8cd](https://github.com/Meterless/Meterless/tree/1742dec56a66e58eef9dda2d2b865823758ca8cd/engines/hmem/reference). Do not copy private HQ records/configuration or install another memory engine. During implementation, select only required public source modules with their license/provenance and reuse the tested compatible Node execution path. A Python-to-local-TypeScript JSON worker is sufficient; no network service or model is required. No reference code is vendored by this planning change.

Actual reference APIs are `new HMEM({persistDir,actor,clock})`, `add({content,source,provenance,chatId,...})`, `query(text,{topN,threshold,chatId})`, `store.get/update/persist`, and `feedback`. `query` returns memory objects and trace; resolve source references from those objects, not the formatted context string alone. Persisted state and ledger must stay outside Git.

Today's `ReviewedCorrection` contains only investigation_id/text/evidence_ids/reviewer/reviewed_at; `InvestigationMemory.recall(company_cik,evidence_ids)` and `remember(correction)` are interfaces only. They lack tenant, fiscal period, as_of, source-version identity, approval decision, idempotency and correction lineage. Do not use this protocol as an authorization boundary. Agree a versioned adapter envelope before implementation; existing interface remains unchanged until then.

The proposed envelope adds trusted server-side `scope_id` (tenant/session + CIK + period + accounting basis), correction_id, source refs/version or hash, as_of, reviewer actor, approval timestamp/decision, and supersedes/supersededBy IDs. Client-supplied reviewer names are not authorization. Before real teammate sharing, establish actual actor identity; a local human approval may use an explicitly selected local actor, labeled accordingly.

Use one isolated store directory/worker per trusted scope, strict envelope validation on every operation and post-filtering on every recall. H-MEM chatId admits unscoped memories and is not tenant isolation; never load another scope into the same store. Reject missing/foreign source references and changed/stale evidence. Revalidate publication cutoff on recall; memory is an interpretation pointer, not a replacement for financial evidence.

Human correction flow: propose → validate citations/scope → explicit approve or reject → idempotent add with provenance origin user_correction and source refs → set new.supersedes AND old.supersededBy → persist/ledger → restart → recall/revalidate → recheck finding. Denial writes no approved memory. Approval must be tied to the exact proposed content/version. Disable automatic conflict resolution, sleep/dream synthesis and unrelated mining for this slice; these could bypass the human gate.

The reference's add/update writes are not an atomic two-record transaction. The adapter needs a small idempotent operation journal and startup recovery before serving recall, so a crash between lineage updates cannot expose half-applied corrections. Keep the old record for audit; after engine ranking, the application excludes superseded records from active corrections. Persist reviewer/source lineage, not secrets or account data.

Reference embeddings are deterministic hash mocks, not learned semantic embeddings. Exercise actual add/query/persistence/feedback and source-linked correction behavior, label retrieval deterministic, and test repeatability. Previously passing13 reference conformance tests do not establish this product behavior. No Nightshift access is necessary for these deterministic memory operations.
