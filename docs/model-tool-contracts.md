# Model tool contracts v1: preparation, no live inference

`backend/investigation/model_contracts.py` defines the versioned untrusted proposal boundary. `shared/model-tools.json` is generated from the actual Pydantic models in Chat Completions function-tool format (`type:function`, `function:{name,description,strict:true,parameters}`). `shared/model-output.schema.json` defines the proposed final output. This packaging prepares a future Meterless/Nightshift extension; the preserved adapter currently accepts text and returns text, and has **not** demonstrated tool calls, structured output, this schema dialect, or live inference. No controller, API, frontend, provider transport or cloud objects are changed by this preparation.

| Model-facing function | Allowed proposal | Independent host responsibility |
| --- | --- | --- |
| `propose_extracted_claims` | At most three source-quote claims with metric, decimal string, unit, basis, exact dates and quote reference | Register trusted disclosure text, canonical URL, publication and reporting dates; validate exact text/hash/spans; retain model provenance and unverified semantic mapping |
| `select_evidence_checks` | Known claim IDs and allowlisted source-date, period, unit, basis, conflict and missing-context checks | Actually execute each check; selection alone is not execution |
| `query_financial_evidence` | Revenue, diluted EPS or net-income metric names | Use immutable run company/year/period/cutoff and the existing approved Zetaris reader; filter permitted metrics, preserve metadata, record failures and source modes |
| `calculate_financial_claim` | Known claim ID, `compare_value` or `gaap_net_margin`, known fact IDs | Recompute with the existing verifier over **all** registered facts so omitted contrary values cannot produce support; reject mismatched operations/citations |
| `request_additional_investigation` | One recorded non-supported claim, matching reason and existing references | Choose bounded approved retrieval, preserve counterevidence, validate/register new results, reverify and rechallenge; no automatic retry |
| `submit_investigation_conclusion` | Every registered claim, host-verdict classifications and matching citations, proposed prose, required review, unverified semantic mapping | Render canonical citation URLs/publication dates and authoritative findings from registry; retain limitations, validate briefing semantics and obtain actual human review |

No function accepts SQL, commands, paths, URLs, company changes, credentials, memory writes or human approval. All external objects reject extra fields and use strict scalar types. Decimal values must be finite bounded strings; the existing verifier's float ingestion limitation remains. Model prose and source text are untrusted content, never instructions to a dispatcher. The gate does not execute query proposals: a future allowlisted host dispatcher must bind them to the existing reader and sanitize its response. No unrestricted SQL access is introduced.

## Trusted registry and quote contract

`ModelProposalGate(request, evidence=(), disclosures=(), clock=...)` snapshots the request and evidence. `scope` returns a defensive copy. `TrustedDisclosure` is a frozen host-ingestion record with ID, text, primary SEC URL, publication date and exact reporting dates. Register only source content fetched through approved ingestion, with independently verified issuer/fiscal scope. The gate checks issuer URL/chronology/cutoff but **does not independently map dates to a company's fiscal calendar**. That mapping remains the trusted reader/ingestion responsibility. This change does not implement disclosure ingestion.

Quote references contain `disclosure_id`, `text_sha256`, `normalization:unicode-codepoints-exact-v1`, `start`, `end`, and `quote`. Hash the exact UTF-8 registered text without normalization; offsets are Unicode code points, zero based and half open. `text[start:end]` must equal the quote, and claim text must equal that quote. Browser UTF-16 offsets must be converted before proposal construction. Each registered disclosure is bounded to 12,000 characters; each quote to 4,000; at most three claims. Model URLs/publication dates are omitted entirely: output citations are resolved by the host, not copied from model prose.

Exact quote membership proves source attribution, **not semantic extraction**. A model may still assign the wrong metric, unit, basis or number to a real quote. `model_extracted_proposal` remains the external input kind. The private adapter to the existing verifier uses its historical `human_assertion` value only to invoke arithmetic; this grants no human authorship, approval or semantic validity. Calculation receipts and final proposals explicitly carry `semantic_mapping_status:unverified` and `human_review_status:required`. A `supported` arithmetic finding cannot be presented as verified extraction or accepted issuer meaning. The host must review semantic mapping and briefing assertions before treating those proposals as source-backed conclusions.

## Gate usage and limits

Pass a parsed JSON object to `gate.validate(tool_name, arguments)`. Unknown tools, extra properties, unknown/duplicate claim and evidence IDs, future or cross-issuer evidence, forged verdicts, quote hashes/offsets and approval attempts fail closed. Reject duplicate JSON keys and bound provider output bytes **before** passing a parsed object; that transport work is not implemented here. Invalid attempts also consume the shared limit of eight proposal calls. The gate enforces its 120-second monotonic deadline and one recheck; the future dispatcher must charge model and retrieval latency to that same deadline, cap transitions at ten, constrain output tokens, terminate blocked workers and stop on failures. A fresh gate is not a legitimate way to reset a run budget.

The host calls `record_completed_challenge()` only after actually running all selected allowlisted checks for every claim. It is deliberately absent from model tools. The hook verifies selections and existing verification results; it cannot independently prove that its trusted caller performed those checks. A recheck invalidates challenge completion. Retrieval results must be registered in an updated trusted snapshot and reverified without resetting consumed run budgets; a secure evidence-update and lifecycle dispatcher is still future work. Current tests exercise the preparation gate in isolation, not a completed live agent loop.

Final model prose is a **briefing proposal**. Matching structured verdicts/citations do not prove that every sentence is supported. The future host must validate/restrict prose claims, render source citations from registered records, preserve contrary findings and unresolved outcomes, and show human review as required. H-MEM reads and approved corrections remain through the existing host workflow; no model can approve or write memories.
